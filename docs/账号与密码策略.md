# 账号、密码与会话安全策略

> 对应 `gj.md` §3.3 / §10 / §17 阶段一「统一密码策略、会话撤销和账号恢复流程」。

## 1. 统一密码策略

后台账号与普通用户**共用同一套校验实现**（`auth.ValidatePassword`），仅最小长度参数不同。

| 参数 | 环境变量 | 默认 |
| --- | --- | --- |
| 后台账号最小长度 | `PASSWORD_MIN_LENGTH_ADMIN` | 12 |
| 普通用户最小长度 | `PASSWORD_MIN_LENGTH_USER` | 8 |
| 最大长度 | `PASSWORD_MAX_LENGTH` | 128 |

校验项：

1. 长度区间（按 Unicode 字符计）；
2. 不得由单一重复字符组成（如 `aaaaaaaa`）；
3. 不得包含用户名（大小写不敏感）。

错误统一包裹 `ErrWeakPassword`，接口返回 422 并指明具体原因。

**应用位置**

| 场景 | 实现 |
| --- | --- |
| 管理员创建 / 重置 | `adminaccount.Create` / `ResetPassword` |
| 管理员自助改密 | `auth.Service.ChangePassword` |
| 普通用户注册 / 改密 | `user.Service.Register` / `ChangePassword` |
| 普通用户管理重置 | `useradmin.ResetPassword` |
| 初始化管理员命令 | `cmd/create-admin` |

## 2. 会话撤销

| 场景 | 行为 |
| --- | --- |
| 自助改密 | 撤销该账号全部会话 |
| 管理员重置密码 | 撤销全部会话 + 强制改密 |
| 改角色 | 撤销全部会话（避免旧角色权限继续生效） |
| 停用 / 删除账号 | 撤销全部会话 |
| 用户主动「退出其它设备」 | `POST /api/v1/admin/auth/sessions/revoke` |
| 查看当前会话 | `POST /api/v1/admin/auth/sessions/list` |

会话 ID 不回显原文，列表仅返回 SHA-256 前 12 位指纹。

## 3. 账号恢复流程

### 3.1 管理员账号

1. 现任管理员在「管理员账号」页执行「重置密码」；
2. 服务端写入新密码哈希，并置 `must_change_password = true`；
3. 服务端撤销该账号全部会话；
4. 操作者通过安全渠道把临时密码交给账号本人（不展示密码哈希或其它秘密）；
5. 账号本人登录后，除「自助改密 / 资料维护 / 登出 / 会话管理」外的后台接口一律返回
   `403 PASSWORD_CHANGE_REQUIRED`；
6. 改密成功后 `must_change_password` 自动清空，并再次撤销会话要求重新登录。

### 3.2 普通用户

与管理员相同（`useradmin.ResetPassword`），改密前其余写操作被 `RequirePasswordChanged` 拦截，
读接口仍可用（便于用户查看自己的数据后决定是否改密）。

### 3.3 风险接受与后续增强

当前**不提供邮箱自助找回**（站点未接入事务性邮件服务）。已知风险与缓解：

- 风险：用户忘记密码只能联系管理员；
- 缓解：管理员重置 + 强制改密已有完整闭环，且全程审计；
- 期限：接入邮件服务后补「一次性重置链接」（token 哈希落库、单次有效、30 分钟过期）。

## 5. 审计要求

以下操作必须写审计（已实现）：

- `admin.login` / `admin.login_failed`
- `admin.reset_password` / `admin.update`（改角色、停用）
- `admin.delete` / `user.delete`
- `admin.revoke_sessions`
- `role.update`（含权限前后差异）

审计日志的查询与导出本身也需审计（见 `docs/审计与安全事件.md`）。
