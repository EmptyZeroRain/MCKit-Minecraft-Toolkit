# 后台操作手册

> 对应 gj.md 阶段四第 4 项「持续完善可访问性、操作帮助和管理文档」。
> 页面内版本：`/admin/help`（`AdminHelpView.vue`），内容与本文保持一致，避免两处说法冲突。

## 1. 角色与权限

- 后台入口按权限点显示；**隐藏只是减少误操作，后端每个接口都会再校验**，越权请求返回 403。
- 权限改动需要**重新登录**才生效（会话中缓存了权限快照）。
- 首次登录若被要求改密：改密成功会注销当前会话；未改密时后台接口会被拦截（写操作额外拦截）。
- MFA 绑定后**恢复码只显示一次**，请立即存入密码管理器；未配置服务端密钥时，已绑定账号会被拒绝登录（安全失败）。

## 2. 日常操作

### 2.1 内容审核

1. 打开「内容审核 / Mod 审核 / 整合包 / 红石设计」，左侧勾选条目（支持全选当前页）。
2. 批量工具条：批量通过 / 批量驳回，可统一填写备注。
3. 单次上限 **50 条**；每条独立事务，**部分失败是正常的**，失败明细会逐条列出，成功项不回滚。
4. 每条成功都会单独写审计，`after` 中带 `batch: true`，便于区分批量与单条。

### 2.2 内容修订与回滚

- 资料详情页的「历史版本」可查看版本列表与差异。
- 回滚 = 把旧快照写回 + 追加一条 `rollback` 版本；**历史不删除**，可以再滚回来。
- 删除前会做一次只读的**影响预览**（关联数据 / 引用数）；预览失败不阻止删除，但会提示「影响未知」，建议先查日志。

### 2.3 数据质量问题

- 检查结果**实时计算**，处理状态单独存（`data_quality_issues`，以 `check_key` 为唯一键）。
- 每个问题项可以：指派负责人、写处理备注、标记已解决 / 忽略 / 重新打开。
- 检查命中数归零时**不会自动关单**（避免抖动误关），需要人工确认；`snapshot_count` 记录处理时的条数，便于对比进度。
- 「去处理」按类别跳转到公开资料页或审核工作台。

## 3. 运维操作

### 3.1 后台任务

- 用于耗时或易失败的动作（链接全量巡检、源码缓存重建）。
- 失败会按指数退避**自动重试**（默认最多 3 次）；仍失败转 `failed`。
- **人工重试会新建一条任务**并记录 `retry_of`，原始失败现场保留，便于对比。
- 执行中的任务**不可取消**；单任务执行上限 30 分钟。
- 已完成任务保留 90 天（`JOB_RETENTION_DAYS`），只有终态会被清理。

### 3.2 运营告警

- 规则每 5 分钟评估一次，也可在页面手动「立即评估」。
- 同一规则**未关闭期间只保留一条**；指标恢复后自动关闭（`resolved_by=system`），历史保留。
- 「确认」表示已有人接手（不会被自动关闭）；关闭时必须写原因，追加到 `detail`。
- 内置规则：失效链接比例、近 24h 失败导入、近 24h 失败后台任务、严重数据质量问题、缓存容量。

### 3.3 MC 源码缓存

- jar / 索引都是**可重建的派生数据**，清理不丢业务数据，只影响下次准备时间。
- 「重建」= 清理 → 重新下载 → 重建索引，作为后台任务执行，进度在「后台任务」页查看。
- 占用达到 `MCSRC_CACHE_ALERT_MB`（默认 4096）会触发容量告警；页面也会即时提示。
- 匿名访客自动准备有版本数上限（`MCSRC_AUTO_PREPARE_MAX`），管理员不受限。

## 4. 审计与导出

- 「操作日志」支持按动作、对象类型、结果、来源 IP 筛选。
- 「安全事件」视图只看登录 / 改密 / MFA / 会话撤销，用于排查账号风险。
- 导出为 CSV（UTF-8 BOM）：资源 / 用户 / 审计；单次上限 5000 条（用户 10000 条），超出时响应头标记截断。
- 以 `= + - @` 开头的单元格会被加单引号，防 CSV 公式注入。
- **导出本身写审计**（`audit.export` / `resource.export`），记录条数与筛选条件。
- 审计不记录密码、Cookie、Authorization、连接串。

## 5. 无障碍与键盘

已完成（本次核查）：

- 所有交互元素使用原生 `button` / `input` / `select`，Tab 顺序与视觉顺序一致；
- 输入框与搜索框均有 `aria-label`（如资源搜索、来源平台）；
- 对话框（`ConfirmDialog`）打开后焦点限制在框内，Esc 关闭，关闭后焦点回到触发元素；
- 表格使用 `scope="col"` 表头，状态除颜色外还有文字标签；
- 结果 / 严重度等关键信息不以颜色作为唯一区分手段。

约定（新增页面必须遵守）：

1. 图标按钮必须有 `aria-label` 或可见文字；
2. 表单控件必须有关联的 `<label>` 或 `aria-label`；
3. 新增状态标签必须同时给出文字，不只用色块；
4. 加载 / 错误状态要有文字说明，不能只靠转圈；
5. 快捷键不得覆盖浏览器与读屏软件默认行为。

## 6. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 菜单看不到 | 角色缺少权限点 | 「角色管理」勾选后重新登录 |
| 改完权限没生效 | 会话内权限快照 | 重新登录 |
| 导出 CSVs 打开乱码 | 未按 UTF-8 解析 | 用「数据 → 从文本/CSV」并选 UTF-8 |
| 告警一直不关闭 | 指标仍未恢复 | 查看指标快照；确认后仍需修复根因 |
| 任务一直 pending | 调度未启动 / 队列积压 | 检查服务日志与 `admin_jobs` 表 |
| 缓存重建失败 | 版本号错误 / 网络问题 | 看任务失败详情（已脱敏），修好后人工重试 |
